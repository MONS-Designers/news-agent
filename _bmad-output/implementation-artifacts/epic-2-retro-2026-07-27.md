## What worked

**An architecture decision made eight stories earlier held under load.** AD-8 - one row per `(kind, field_id, normalized_text)` scoped to `status='pending'`, backed by a partial unique index - was written in Story 1.1. In Epic 2 it paid off twice: the read path needed no `GROUP BY` (no second, divergent definition of "the same submission"), and Story 2.2's AC #5, "a resubmission after a decision opens a fresh pending row", required **zero implementation** - only a test. This is the clearest evidence so far that the up-front data-shape decisions in the architecture spine were worth their cost.

**Reuse over reinvention, consistently.** `TaxonomyQueueView.vue` was copied structurally from `AdminView.vue`; `decide_pending_suggestion` leaned on the existing get-or-create behaviour of `add_field`/`add_role` rather than reimplementing "create or reuse"; the two new error classes copied the `detail`-dict shape of `TopicCapExceededError`. An entire epic shipped without inventing a new pattern.

**Story 2.2's ambiguities were resolved before implementation, not during.** Both product decisions (orphan roles, editable promoted name) were surfaced while writing the story file and decided with the project lead, so implementation ran straight through.

## What did not work

### 1. CI was red for four stories and the process did not notice

CI failed on every push from Story 1.4 through Story 1.7. The cause was not code: `ruff` was unpinned in `requirements-dev.txt`, CI installed `ruff 0.16.0`, and that release widened ruff's *default* rule selection to include `B`, `I`, `UP` and `RUF` - producing 38 errors across 17 untouched pre-existing files, 19 of them `B008` against FastAPI's own `Depends()` idiom.

Detection latency was roughly four stories, and the detection came from the project lead, not from the workflow. Every one of those stories ended with a commit; none checked whether the previous commit's CI run had passed.

Fixed in `d60efe5` by pinning the version (fixes *who* lints) and declaring `[tool.ruff.lint] select` explicitly (fixes *what* is linted).

### 2. Story specs miss what the real data reveals - three stories running

| Story | What the spec assumed | What the data actually contained |
|---|---|---|
| 1.7 | `TopicsStep` fetches when the user reaches it | all steps mount at page load via `v-show`, so it fetched immediately |
| 2.1 | a null `field_name` implies a field-kind row | a `kind='role'` row with `field_id=NULL` already existed |
| 2.2 | every suggestion has a reasonable display string | two rows carry only casefolded `normalized_text` |

In all three cases `vue-tsc`, `mypy` and the full test suite were clean. Only live verification caught them.

**Root cause:** story files are written from `epics.md` and the architecture spine, which describe the *model* - not the *states the data is actually in*. The orphan role row was sitting in the dev DB before Story 2.1 was even written. Nothing in the story-creation process looks at it.

### 3. Live verification for Story 2.2 was destructive with no undo

Promote and dismiss are one-way; there is no un-decide path. Verification consumed real queue rows and required a manual record-state-then-restore procedure. This works but is fragile, and it exists because verification rides on data that accumulated organically from earlier stories rather than on a seeded fixture.

### 4. Dev-environment friction absorbed silently instead of being fixed

The backend in `.claude/launch.json` runs `uvicorn` **without `--reload`**, so every backend change - especially a new route - forces a full restart, which forces contention over port 8000 with whichever session holds it. This caused three separate tangles across Epic 2 and was treated as a port problem for two whole stories rather than being named as the configuration bug it is. Raised by the project lead during this retrospective.

The related papercut: `PYTHONPATH=src` is required before every backend command because the editable install resolves to a stale worktree (recorded in `deferred-work.md` since Story 1.1 and never acted on).

### 5. No frontend test runner exists

Every frontend acceptance criterion in Epics 1 and 2 was verified by hand in a browser. Deliberately not changing this now (see Action 4), but it is the reason every frontend defect in both epics was found late.

## Action items

**1. Add `--reload --reload-dir src` to the backend launch configuration.**
Owner: Claude · Needs: approval to edit `.claude/launch.json` · Success: a backend code change is picked up without restarting the process or touching port 8000.
`--reload-dir src` is required, not cosmetic - uvicorn otherwise watches the whole working directory, and story `.md` writes plus `newsagent.db` changes would trigger constant reloads.

**2. Repair the editable install so `PYTHONPATH=src` is unnecessary.**
Owner: Nomi (touches the venv) · Success: `pip show newsagent` resolves to `C:\project\news-agent`, and `python -m newsagent.cli` and `alembic` run the current branch's code from a plain shell.

**3. Add a mandatory real-data review step to story creation.**
Owner: Claude · Success: every new story file contains a section listing the states the story's tables are *actually* in, queried from the dev DB, plus which of those states the acceptance criteria cover. Decided in this retro over the alternative of investing in frontend unit tests.
This is the direct countermeasure to failure #2 above; all three of those defects were visible in the data before the story was written.

Owner: Nomi (decision) · Rationale: live verification has caught every frontend defect in two epics, and the surfaces are small. Revisit if the frontend grows past the current handful of views.

## Key takeaways

1. **Data-shape decisions made early compound.** AD-8 removed work from two later stories and made one acceptance criterion free.
2. **Type-checkers and unit tests cannot see the shape of production data.** Three consecutive stories shipped a wrong assumption that every automated gate passed and one browser session caught.
3. **An unpinned tool is an unpinned policy.** A linter upgrade changed what the project enforces without a single commit.
4. **Repeated environment friction is a bug report, not a cost of doing business** - it went unnamed for two stories because it was easier to work around each time than to look at the cause.
