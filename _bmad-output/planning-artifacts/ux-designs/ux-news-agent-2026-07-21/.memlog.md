- (decision) Confirmed: when a user selects 'Other' for Role (or Field), they fill it manually as free text -- no interim non-LLM suggested-Role list is needed. Resolves PRD open question re: interim Role behavior before the Suggestion Source is LLM-connected.
- (decision) Flow ordering: user fills Interest Free-Text (if any) BEFORE the system computes Topic suggestions -- suggestion generation waits for the full profile section (Field/Role/Experience/Interest Free-Text) rather than firing right after Field+Role alone. This is what lets the suggestion pool be properly capped at 4.
- (decision) Admin stays the sole owner of the Role/Field curation queue for now, indefinitely -- no automatic LLM/DB-driven takeover of Role-list growth. Future automation (LLM or DB analytics detecting a need for more roles) is tracked as a separate GitHub issue, not built now.
- (decision) Visual direction brief (Sally): fresh, highly interactive, 'most advanced and attractive' look, superior professional finish -- explicit departure from both the current spartan neutral-Tailwind preferences page and the unrelated dark/gold 'Midnight' email brand. Independent visual identity for this feature.
- (decision) Visual direction approved: 'Hybrid Depth' -- near-black base, 3 soft glowing orbs (indigo/teal/plum, not neon) with mouse+scroll-driven parallax, faint dot-grain texture, restrained typography/copy. Combines restraint of 'Crisp Minimal SaaS' with the interactive 'game' quality of 'RPG Class Select', delivered via motion/depth rather than color or playful copy. Serious + mysterious + professional, per user brief.
- (decision) Interaction model: profile setup is a 3-step flow, one step visible on screen at a time, each with a staggered fade-up entrance animation on its elements. Steps: (1) Field + Role + Experience together, (2) Interests, (3) Topics. Confirmed via working prototype flow-hybrid-depth-steps.html -- Field selection dynamically populates Role options, step transitions work, progress indicator tracks current/done steps.
- (decision) Each step includes a 'Skip for now' link alongside Continue, to preserve the PRD's 'everything optional, nothing blocks saving' guarantee even though the primary path encourages completing each step before advancing.
- (event) Verified interactively in the Browser pane: Field click populates Role chips per field, Continue enables after Field selection, step transitions animate and update progress indicator, Topics step shows 4 picked + swappable faint candidates. Working file: .working/flow-hybrid-depth-steps.html.
- (event) Opened GitHub issue #29 (MONS-Designers/news-agent) tracking future automation of Role-list growth detection, per user confirmation.
- (override) Step navigation: Back is always available, but Continue is now GATED -- user cannot advance past a step until every field in that step is filled ('all fields are mandatory'). Reverses the 'Skip for now' link added earlier for Field/Role/Experience (step 1). Applied unambiguously to step 1 (Field + Role + Experience all required to unlock Continue).
- (assumption) Whether 'all fields mandatory, no skipping forward' also applies to Interest Free-Text (step 2) is NOT yet confirmed -- flagged back to user, since it reverses PRD FR-4 (Interest Free-Text explicitly optional) and recreates the exact 'blank textarea is homework' cold-start friction the Field/Role picker was designed to solve by coming first. Step 2's Skip link left in place pending confirmation.
- (event) Step-1 mandatory-fields gate verified programmatically: Continue blocked with 0/3 fields set, unlocks only once Field+Role+Experience all set, Back always works regardless. Fixed an underlying bug in the process -- div-based buttons don't support the native 'disabled' attribute/:disabled CSS pseudo-class (those only apply to real form controls), so the original gating was purely cosmetic. Now uses a real .disabled class checked inside the click handler.
- (decision) Confirmed: Interest Free-Text (step 2) stays optional -- Skip link remains, no forward-gate. Only step 1 (Field + Role + Experience) requires all three filled before Continue unlocks. Resolves the prior open assumption.
