- (decision) 3-bullet article body with <strong> keyword emphasis IS in scope. Requires extending the LLM SummaryResult contract (#5/#11) so the provider returns structured bullets + keyword marking, not a free-text paragraph. Cross-issue change accepted by user.
- (decision) Rule of 5: pick top-5 articles per digest by a WEIGHTED score of relevance + recency + interest (ענין). Relevance exists (relevance_score); recency derivable from published_at; 'interest' is a NEW undefined signal — needs definition.
- (decision) Date: Gregorian only in Hebrew format (e.g. 20 ביולי 2026). No Hebrew (lunar) calendar date needed.
- (question) What is the 'interest' (ענין) signal in the weighted ranking? Options: (a) a general LLM interestingness score separate from topic relevance; (b) per-user personalization from open-tracking (opened_at) history; (c) source authority weighting. And what are the three weights?
- (decision) 'Interest' signal = BOTH (a) a general LLM interestingness score (new field on SummaryResult / LLM contract, 0-1, distinct from topic-relevance) AND (b) per-user personalization from opened_at history. This makes final ranking PER-USER and is the first real consumer of the #13 open-tracking data.
- (decision) Weights: sensible default + env config (user delegated). Proposed default final_score = 0.40*relevance + 0.25*recency + 0.35*interest; recency = exponential decay (24h half-life) from published_at; interest = 0.6*llm_interestingness + 0.4*personalization_affinity; personalization_affinity defaults to neutral 0.5 when user has no open history. All weights env-overridable.
- (note) SCOPE IMPLICATION: the weighted per-user ranking engine (recency decay + interest composite + personalization from opened_at) is substantial and crosses the LLM contract (#5/#11 add interestingness) + digest builder (#12 gains a ranking/top-5 step). This is bigger than email UX #13 and should be its own implementation issue. #13 email only needs to consume 'top-5 ranked articles' as input.
- (decision) Weighted per-user ranking engine → its own separate issue (like images). #13 email consumes 'top-5 ranked' as input only.
