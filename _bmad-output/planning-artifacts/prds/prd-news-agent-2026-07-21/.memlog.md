- (decision) Feature lives in existing self-serve preferences page (GET/PUT /me/preferences, #21), always editable — not a one-time registration wizard. Reason: onboarding friction risk; profile changes over time.
- (decision) Taxonomy is 2 required levels only: professional Field -> Role. A 3rd 'specialization' level was proposed and explicitly rejected by user as unnecessary.
- (decision) Field/Role lists are admin-curated (fixed lists), mirroring existing admin source-approval pattern (#22). PM (John) authors the initial list generically to cover most common fields/roles -- no real dogfood-user field/role data available yet. [ASSUMPTION]
- (decision) Role selection includes an 'Other' free-text option; submissions queue for admin review to promote frequent entries into the curated list (same approval-loop pattern as #22).
- (decision) Years-of-experience is captured as a bucket (not raw number), for PM/product statistics only. Explicitly does NOT weight or influence category suggestions -- user confirmed no differential scoring by experience.
- (decision) Category suggestion: (field, role) fed to an LLM, computed asynchronously (not blocking page/save) -- pre-checks items in the existing preferences toggle grid; user can always override.
- (decision) Free-text 'describe your interests' -> LLM is explicitly deferred (later phase), not built in this slice. Reason: validated-first with structured picker since free text is a hard cold-start for users.
- (decision) Stakes: internal for now (small real user base, dogfood), but designed with an eye toward eventual broad distribution -- avoid hobby-grade shortcuts that would block scaling later.
- (decision) Working mode: Fast path selected by user (batch questions, draft with [ASSUMPTION] tags, user corrects afterward).
- (event) Fast-path draft of prd.md and addendum.md written; presented to user for correction pass.
- (override) Field now DOES support an 'Other' free-text option (reverses earlier FR-2 Out-of-Scope assumption that Field stays fully closed). Field's Other submissions queue for admin review same as Role's.
- (override) Free-text 'describe your interests' -> LLM feature is pulled into THIS feature's current scope (reverses earlier deferral to a later phase, per user: 'now').
- (decision) Role options (taxonomy level 2, scoped under selected Field) are generated by a pluggable Suggestion Source (LLM-backed once connected) rather than a fixed admin-curated static list. Field remains a fixed admin-curated list. 2 stored taxonomy levels confirmed final (no 3rd stored 'specialization' field).
- (decision) LLM integration is structurally in MVP scope, but the actual local LLM model is not yet selected/connectable (task-sequencing constraint). Build all surrounding infrastructure/UI/wrapper now; the Suggestion Source must be a pluggable interface so connecting the real LLM later requires no UI/data-model rework. This local LLM is a separate model from the one used for article summarization/translation.
- (decision) Topic selection hard cap: user may select at most 4 Topics total (platform-wide, combining suggestion sources), replacing the previously unlimited toggle grid. User can swap which of the (at most 4) suggested Topics they keep.
- (assumption) Until a Suggestion Source is LLM-connected: Role-level-2 suggestions and Interest-Free-Text-driven suggestions produce no output (user relies on 'Other' free text for Role in the interim); Topic suggestions still always produce output via a non-LLM popularity-based default ('things that interest most people'). Needs user confirmation.
